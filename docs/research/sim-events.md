# Simulation Events — Canonical Inventory

> Snapshot as of 2026-04-19. Generated by parallel research for the sim-vs-reality audit.

## How to read this document

Each event has: **Name** · **Type string** (as stored in `simulation_events.type` or equivalent) · **Trigger** · **Cadence/timing** · **Actor** · **Code reference** (file:line).

Agent actions (the 12 `AgentAction` union variants) and injection types are listed separately. Flags:

- `(⚠ defined but not created)` — declared in the `SimulationEventType` union but no `addEvent({type: "..."})` call exists.
- `(⚠ invisible to users)` — emitted but NOT listed in `EVENT_CATEGORIES` in `packages/web/src/pages/NewsFeed.tsx`.

## 2. Daily loop (`runDay` sequence)

Scaffolded against the 13-step flow in `.claude/rules/simulation.md`. Every event emitted in `packages/engine/src/simulation/loop.ts` is listed in first-encounter order.

### Step 0 — Setup (load state, cleanup partial day, migrate DB)

No events. `cleanupPartialDay()` deletes stale rows if a previous attempt aborted.

### Step 1 — Day open

- **`day_start`** (`loop.ts:239`) — actor `system`. Always emitted first and flushed to DB immediately so the frontend knows the day is processing. Also re-used as a fallback event type for:
  - Injected invalidation notice (`loop.ts:406`)
  - Injected snap election notice (`injections.ts:59`)
  - Injected invalidate-election notice (`injections.ts:69`)
  - Referendum resolution events (`referendums.ts:188` — comment says `// reuse existing type for referendum events`).

Also upserts `day_summaries(preview, …)` row with a deterministic start-of-day preview string (`loop.ts:281`).

### Step 2 — Economic drift + provisional-budget drag

- **`economy_update`** (`loop.ts:296`) — actor `system`. Emitted every day after `applyEconomicDrift()`. Also emitted by `injections.ts:97` for an injected economic shock.

### Step 3 — Process pending injections (consume `pending_injections`)

From `injections.ts`:

- **`crisis_start`** (`injections.ts:45`) — from injected `crisis` row (data=`{templateId}`). Tagged `injected: true`.
- **`day_start`** (`injections.ts:59`) — from injected `election` row (`triggerElection`).
- **`day_start`** (`injections.ts:71`) — from injected `invalidate_election` row.
- **`budget_proposed`** (`injections.ts:83`) — from injected `budget` row (admin-forced cycle).
- **`economy_update`** (`injections.ts:97`) — from injected `economic_shock` row.

Injected crisis row also causes another emission path at `loop.ts:467` if a new crisis is generated by `maybeTriggerCrisis()`.

### Step 3b — Election invalidation (if `injections.invalidateElection`)

- **`day_start`** (`loop.ts:406`) — titled "Wahl durch Gerichtsbeschluss annulliert" (`⚠` overloaded type). Restores pre-election seat counts and sets `nextElectionDay = currentDay`.
- **`fraktion_formed` / `fraktion_dissolved`** — via `updateFraktionen()` (`loop.ts:394`).

### Step 3c — Crisis lifecycle

- **`crisis_end`** (`loop.ts:430`) — when `currentDay >= endDay`. Actor `system`, data `{crisisId, templateId}`. `resolveExpiredCrises()` in `crises.ts:107`.
- **`crisis_start`** (`loop.ts:469`) — new crisis from `maybeTriggerCrisis()` (daily 8 %, monthly day adds 25 %). Immediate sentiment hit of 1/2/3 depending on severity. Also creates a `crisis_alert` user notification (`createNotificationForAll`).
- **Daily crisis impact** — `applyCrisisImpacts()` mutates economy + sentiment in-place; no event.

### Step 4 — Election system

`shouldTriggerElection()` fires if `currentDay >= nextElectionDay`, or `lowSentimentStreak >= 5` and no cooldown.

- **`election_announced`** (`loop.ts:529`) — actor `system`. Also notifies all users (`election_started`).
- **`election_campaign`** (`loop.ts:1394`) — *per AI `campaign_statement` action* during active campaign phase. Actor is the partyId.
- **`election_campaign`** (`elections.ts:81`) — actor `system`. Emitted by `advanceElectionPhase()` when day reaches `campaignStartDay` (status `announced → campaign`).
- **`election_result`** (`loop.ts:871`) — actor `system`. On election day, `calculateResults()` (Gaussian noise + 5 % threshold + proportional seats). Also notifies all users.

Then status moves to `negotiation` for up to `MAX_NEGOTIATION_ROUNDS` sim days.

- **`negotiation_round`** (`negotiations.ts:283`) — one event per party per round, actor = partyId. Built via `buildNegotiationEvents()`. `runNegotiationRound()` is a **batched AI call** (submitBatch) using the `negotiation` model.
- **`negotiation_complete`** (`loop.ts:752`) — AI synthesis (Sonnet) OR algorithmic fallback.
- **`government_formed`** (`loop.ts:608` emergency fallback / `770` normal). Also creates a `government_formed` user notification.
- **`government_cabinet_formed`** (`loop.ts:621` emergency fallback / `784` normal). Chancellor + 8 ministers (`formCabinet()`).
- **`fraktion_formed` / `fraktion_dissolved`** — via `updateFraktionen()` on seat changes (`loop.ts:616` / `762`).

Safety path: if negotiations stuck for `> MAX_NEGOTIATION_DAYS`, force-complete with `government_formed` labelled "Notfall-Rückfalloption".

### Step 5 — Bill pipeline (`advanceBillPipeline` in `bill-pipeline.ts`)

Runs only when `!skipPartyAgents`. Transitions gated by `statusChangedOnDay < currentDay`.

- **`bill_first_reading`** (`bill-pipeline.ts:72`) — `proposed → first_reading`. Skipped for government bills (they jump to committee).
- **`bill_committee`** (`bill-pipeline.ts:54`) — government bill fast-track `proposed → committee`.
- **`bill_committee`** (`bill-pipeline.ts:107`) — normal `first_reading → committee`. Assigns committee + AI-ish recommendation.
- **`bill_committee_rejected`** (`bill-pipeline.ts:137`) — opposition non-govt bill with "reject" recommendation, 40 % chance; bill → `rejected`.
- **`bill_second_reading`** (`bill-pipeline.ts:159`) — `committee → second_reading`.
- **`amendment_voted`** (`bill-pipeline.ts:185`) — one per amendment when 2nd-reading bill advances; tally via `tallyAmendmentVotes()`.
- **`bill_third_reading`** (`bill-pipeline.ts:212`) — `second_reading → third_reading`. Creates `mdb_vote_needed` notifications for every human-seat holder (`bill-pipeline.ts:225`).

### Step 5b — MdB parliamentary actions (`processMdbActions`, user-submitted via `pending_injections`)

From `mdb-actions.ts`:

- **`motion_submitted`** (`mdb-actions.ts:95`) — `mdb_motion` pending injection, `data.mdb = true`.
- **`motion_passed` / `motion_rejected`** (`mdb-actions.ts:101`) — immediate algorithmic tally (`tallyMotionVotes`).
- **`interpellation_filed`** (`mdb-actions.ts:146`) — `mdb_interpellation` pending injection; if minister exists.
- **`amendment_proposed`** (`mdb-actions.ts:187`) — `mdb_amendment` on second-reading bills.

### Step 6 — Party agent batch (single AI batch with all 6 party requests)

`buildPartyAgentRequests()` → `submitBatch()`. Before the batch: optional knowledge-grounding digest, committee seeding, era summary (AI), and daily briefing (AI — shared context). Results processed per party.

Per-party actions emitted:

- **`bill_proposed`** (`loop.ts:1194`) — from `propose_bill` action. Data includes `isGovernmentBill`. Also mirrored to `internal_proposals` caucus list (`iprop-ai-...`).
- **`amendment_proposed`** (`loop.ts:1237`) — from `propose_amendment` action on a 2nd-reading bill.
- **`vote_cast`** (`loop.ts:1266`) — one per party per 3rd-reading bill. Auto-abstain fallback injected for missing votes (`action-parser.ts:386-398`).
- **`bill_passed` / `bill_rejected`** (`loop.ts:1327`) — after tally (`tallyVotes()` — factors in human/bot MdB votes, whipped levels, proxy defaults). Notifies any user who signaled on the bill (`bill_outcome`).
- **`presidential_veto`** (`veto.ts:34`) — 1–6 % probability on passed bills; marks bill `rejected` with `vetoedByPresident: true`, proposer −0.5.
- **`statement`** (`loop.ts:1384`) — from `statement` action, actor = partyId.
- **`election_campaign`** (`loop.ts:1394`) — from `campaign_statement` action during campaign phase.
- **`motion_submitted`** (`loop.ts:1454`) — from `submit_motion` action. Same-day tally.
- **`motion_passed` / `motion_rejected`** (`loop.ts:1463`) — immediate outcome.
- **`interpellation_filed`** (`loop.ts:1506`) — from `file_interpellation` action. Requires minister matching `targetMinistry`.
- **`confidence_vote_filed`** (`loop.ts:1556`) — from `call_vertrauensfrage` action (coalition leader only).
- **`confidence_vote_passed` / `confidence_vote_failed`** (`loop.ts:1565`) — tallied by `tallyVertrauensfrage()`.
- **`government_dissolved`** (`loop.ts:1581`) — if Vertrauensfrage fails, schedules snap election next day.
- **`confidence_vote_filed`** (`loop.ts:1631`) — from `file_misstrauensvotum` action (opposition only), data includes `proposedChancellor`.
- **`confidence_vote_passed` / `confidence_vote_failed`** (`loop.ts:1638`) — tallied by `tallyMisstrauensvotum()`.
- **`government_dissolved`** (`loop.ts:1655`) — if Misstrauensvotum passes, new opposition-led government formed without election.
- **`government_formed` + `government_cabinet_formed`** (`loop.ts:1699` / `1708`) — after successful Misstrauensvotum.
- **`constitutional_challenge_filed`** (`loop.ts:1763`) — from `file_constitutional_challenge` action. Bill must be passed within last 14 days.
- **`constitutional_court_ruled`** (`loop.ts:1772`) — immediate ruling (30 % strike-down). On `struck_down`: bill status updated, economic impact reversed via `reverseBillImpact()`, sentiment −0.5 + |publicSentiment impact|.

### Step 6b — MdB speeches evaluation (batch AI, classifies as ±0.1 / 0)

- **`mdb_speech`** (`speeches.ts:155`) — one per submitted speech, actor = user displayName. Data `{userId, billId, reading, sentimentImpact, impactLabel}`. Pre-filter skips very short speeches; AI flags spam/negative in batch. `(⚠ invisible to users)` — not in `EVENT_CATEGORIES` — wait, it IS listed under `legislative`.

### Step 6c — User-driven AI batches (independent of party-agent batch)

- `answerPendingQuestions()` — batched AI answer per party, up to `QUESTION_MAX_ANSWERS_PER_DAY`. Does NOT emit sim events (answers stored on `citizen_questions`). User notifications sent.
- `maybeGenerateBotQuestionPool()` — AI-generates tagged questions bots can pick. No events.
- `reviewInternalProposals()` — batch "rank + accept top N" per party. Emits to `simulation_events` directly via `db.insert(...)`:
  - **`member_proposal_accepted`** (`internal-proposals.ts:176`) — creates a new bill row (`memberInitiative: true`, `proposerDisplayName`). Sends `proposal_accepted` user notification.
  - **`member_proposal_declined`** (`internal-proposals.ts:209`) — sends `proposal_declined` user notification.
  - **(no event)** — expired proposals (< 3 votes past reviewByDay) just flip status, send `proposal_expired` notification.
- `reviewMdbApplications()` — batch AI per party picks top applications. No sim event emitted (user notifications only).
- `reviewPartyDiscipline()` — every 7 sim days. Batch AI produces reasoning text; no sim event. Sends `mdb_discipline` and `mdb_expelled` user notifications (`discipline.ts:211` / `239`).

### Step 6d — Interpellations answered / expired

- **`interpellation_answered`** (`loop.ts:1865`) — actor = targeted minister's party. Up to 2/day via batch AI `answerPendingInterpellations()`. Sentiment impacts `INTERPELLATION_IMPACTS.kleine`/`.große`.
- **`interpellation_expired`** (`loop.ts:1881`) — actor `system`. Fires when `currentDay - dayNumber > 14` and still pending. Target party takes `INTERPELLATION_IMPACTS.expired` approval hit.

### Step 7 — Approval drift, sentiment drift, inactivity tracking

`applyDailyApprovalDrift(parties, partyActions)` and `applySentimentDrift(publicSentiment)`. Sentiment clamp 5–75, baseline 45, mean-reversion 3 %/day. No events.

### Step 8 — Mid-cycle batch (weekly polls + monthly referendum)

- `resolveExpiredPolls()` — no events, just writes `active=false`, applies winner approval boost.
- `resolveExpiredReferendums()` — emits **`day_start`** (`referendums.ts:188`) — referendum status is `passed` / `rejected` / `expired`, title e.g. `Referendum passed: "…"`. `(⚠ type overloaded — referendum uses "day_start" instead of its own type; IMPORTANT_EVENTS lists "referendum" but no code emits it)`.
- **`weekly_report`** (`loop.ts:1981`) — actor `system`. Fires on poll day (every 15 d, snapped to workday). Triggers `weeklyOpinionRecalc()` (proposer +0.3, opposition +0.5 if sentiment < 40, coalition −0.5 if sentiment < 30) + party preference poll creation (deterministic) + context poll batch AI.
- **`monthly_report`** (`loop.ts:1996`) — actor `system`. Every 30 d (`isMonthlyDay`).

Mid-cycle batch also generates a referendum (AI) every 30 sim days if none active (`referendums.ts:214`). Referendum creation itself is not a sim event — only its resolution reuses `day_start`.

### Step 9 — Budget cycle (annual) + revision retry

- **`budget_passed`** (`loop.ts:2070`) — if `tallyBudgetVote()` passes. Coalition-weighted 300 B EUR allocation. Applies `applyBudgetEconomicEffect()`, sentiment +0.5, clears `budgetRetryDay`. Sends `budget_outcome` user notification.
- **`budget_rejected`** (`loop.ts:2070`) — first rejection (immediately before `provisional_budget_started`).
- **`provisional_budget_started`** (`loop.ts:2045`) — on first rejection: sets `provisionalBudget=true`, `budgetRetryDay = currentDay + 7` (snapped to workday). Asymmetric approval penalties: leader −0.5, junior partners −1.0, opposition +0.3.
- On retry day: revised allocations, `tallyBudgetVote(..., isRevision=true)`. Emits **`budget_passed` / `budget_rejected`** (`loop.ts:2148`).
- **`budget_revision_rejected`** (`loop.ts:2108`) — revision failed. Public sentiment −2, coalition approval −1.5 each. Escalates:
- **`government_dissolved`** (`loop.ts:2120`) — "Haushaltskrise" — sets `nextElectionDay = currentDay` (snap election).

### Step 10 — Sidejobs (every 30 sim days)

- **`sidejob_scandal`** (`sidejobs.ts:111`) — per controversial sidejob discovered by AI batch call. Actor = seat's party. Approval −0.2 to −0.5 (`applySidejobScandalImpact`). `(⚠ invisible to users)` — not in `EVENT_CATEGORIES`.

### Step 11 — Save state, media + summary batch

- **Media articles** — `generateDailyMedia()` / `buildMediaBatchRequest()` generates 2–3 AI articles (`Berliner Tagesspiegel` / `Volksstimme` / `Wirtschaftswoche`). Stored in `media_articles`. **Does not emit a `simulation_event`** (media is a separate surface). `media` is listed in `ROUTINE_EVENTS` but no event is created `(⚠ defined but not created)`.
- `applyMediaSentimentFromArticles()` moves sentiment ± up to 0.5/day.
- **Daily summary** — `buildSummaryBatchRequest()` returns `{narrative, mood}`, stored as JSON in `day_summaries.narrative + .mood`. **Not a sim event**.

### Step 12 — Persist

All `dayEvents` flushed to `simulation_events` (skipping the already-flushed `day_start`). `simulation_meta.currentDay` finally advances; `dayProgress = 100`.

### End-of-day notifications sent to all users

Summary of `createNotificationForAll()` calls:

- `crisis_alert` (`loop.ts:476`)
- `election_started` (`loop.ts:536`)
- `government_formed` (`loop.ts:777`)
- `election_result` (`loop.ts:878`)
- `budget_outcome` (`loop.ts:2077`)

Per-user `createNotification()` calls (`event-queue.ts`):

- `mdb_vote_needed` — 3rd-reading bill open (`bill-pipeline.ts:225`)
- `proposal_expired` / `proposal_accepted` / `proposal_declined` (`internal-proposals.ts`)
- `mdb_discipline` / `mdb_expelled` (`discipline.ts`)

## 3. Legislative cycle (bill pipeline)

A bill progresses: `proposed → first_reading → committee → second_reading → third_reading → passed | rejected | struck_down`. Government bills skip 1st reading.

`BillStatus` (`packages/types/src/types/bills.ts`): `proposed`, `first_reading`, `committee`, `second_reading`, `third_reading`, `passed`, `rejected`, `struck_down`.

| Event | Type string | Trigger | Code ref |
|---|---|---|---|
| Bill proposed | `bill_proposed` | Party agent `propose_bill` action OR accepted member proposal | `loop.ts:1194`, via `member_proposal_accepted` creates bill `internal-proposals.ts:154` |
| Govt. fast-track → committee | `bill_committee` | `isGovernmentBill` skips first reading | `bill-pipeline.ts:54` |
| First reading | `bill_first_reading` | Next day after proposal (non-govt) | `bill-pipeline.ts:72` |
| Committee assignment | `bill_committee` | Next day after 1st reading | `bill-pipeline.ts:107` |
| Committee rejection | `bill_committee_rejected` | opp non-govt bill + "reject" recommendation, 40 % | `bill-pipeline.ts:137` |
| Second reading | `bill_second_reading` | Next day after committee (if not committee-rejected) | `bill-pipeline.ts:159` |
| Amendment proposed | `amendment_proposed` | AI `propose_amendment` action OR MdB `mdb_amendment` | `loop.ts:1237`, `mdb-actions.ts:187` |
| Amendment voted | `amendment_voted` | Per-amendment when moving 2nd→3rd reading | `bill-pipeline.ts:185` |
| Third reading | `bill_third_reading` | Next day after 2nd reading | `bill-pipeline.ts:212` |
| Vote cast | `vote_cast` | Each party's AI vote on a 3rd-reading bill | `loop.ts:1266` |
| Bill passed | `bill_passed` | Tally yesSeats > noSeats | `loop.ts:1327` |
| Bill rejected | `bill_rejected` | Tally fails | `loop.ts:1327` |
| Presidential veto | `presidential_veto` | 1–6 % chance on passed bill (`shouldPresidentVeto` in `budget.ts`) → bill flipped to `rejected` + `vetoedByPresident=true` | `veto.ts:34` |
| Bill struck down | (`bill_rejected` NOT emitted) but `constitutional_court_ruled` decision=`struck_down` updates status to `struck_down` | `file_constitutional_challenge` action | `loop.ts:1770-1798` |
| Bill debate | `bill_debate` | `(⚠ defined but not created)` — referenced only in NewsFeed filter | types/meta.ts:3 |

Additional bill sub-flows:

- **MdB votes (human + bot)** tallied via `tallyVotes(bill, parties, mdbVoteEntries, humanSeatCounts)` in `voting.ts`. Proxy default `party_line` used for non-voting human seats. Discipline level 3 forces vote to party line.
- **Member signal** (YES/NO bar on 2nd/3rd reading) — written to `member_signals`, injected into agent prompt context (`AgentContext.memberSignals`), triggers `bill_outcome` notification. No sim event.

## 4. Election & coalition cycle

Phases in `Election.status`: `announced → campaign → voting → negotiation → completed` (plus `invalidated`).

| Event | Type string | When | Actor | Code ref |
|---|---|---|---|---|
| Announcement | `election_announced` | `shouldTriggerElection()` returns true — scheduled (day ≥ nextElectionDay), snap (low sentiment 5-day streak), or injected (admin) | `system` | `loop.ts:529` |
| Campaign start (system) | `election_campaign` | `advanceElectionPhase` when `currentDay ≥ campaignStartDay` | `system` | `elections.ts:81` |
| Campaign statement (party) | `election_campaign` | Party agent `campaign_statement` action during `campaign` status | partyId | `loop.ts:1394` |
| Election day results | `election_result` | `currentDay ≥ electionDay`, status `campaign → voting`; `calculateResults()` (Gaussian noise + 5 % threshold + proportional 735 seats) | `system` | `loop.ts:871` |
| Negotiation round | `negotiation_round` | Every sim day in `negotiation` status, until `MAX_NEGOTIATION_ROUNDS` reached | partyId | `negotiations.ts:283` |
| Negotiation complete | `negotiation_complete` | After max rounds: AI synthesis (Sonnet) → `CoalitionAgreement`; fallback: algorithmic `formGovernment()` | `system` | `loop.ts:752` |
| Government formed | `government_formed` | Emitted at negotiation completion AND after successful Misstrauensvotum AND as emergency fallback | `system` | `loop.ts:608, 770, 1701` |
| Cabinet formed | `government_cabinet_formed` | `formCabinet()` assigns Chancellor + 8 ministers | `system` | `loop.ts:621, 784, 1710` |
| Seats reallocated | (no event) | `resetAllSeats()` + `allocateSeats()` per party based on election results and preset human/bot ratio | — | `loop.ts:793-797` |
| Fraktion form/dissolve | `fraktion_formed` / `fraktion_dissolved` | `updateFraktionen()` post-seat change | partyId | `fraktionen.ts:68/88` |
| Invalidation | (reuse `day_start`) | Injected `invalidate_election`; rewinds seat counts, sets next election day to today | `system` | `loop.ts:404` |
| Emergency fallback coalition | `government_formed` (data.fallback=true) | Negotiation stuck > `MAX_NEGOTIATION_DAYS` | `system` | `loop.ts:606` |
| Snap-election pre-notice | `day_start` | Injected election (`injections.ts:59`) or post-Vertrauensfrage/budget-revision-failure | `system` | — |

Cooldown: `ELECTION_COOLDOWN_DAYS` — snap elections blocked during honeymoon period right after a new government forms (`loop.ts:599`).

## 5. Government actions (confidence, veto, court)

### Vertrauensfrage (chancellor-initiated confidence vote)

Action: `call_vertrauensfrage` (coalition leader only, max 1/turn, blocked during active election). Tally: `tallyVertrauensfrage()` — 10 % coalition defection chance. Threshold 368 seats.

- **`confidence_vote_filed`** + **`confidence_vote_passed`** / **`confidence_vote_failed`** (`loop.ts:1556`, `1565`).
- If failed: **`government_dissolved`** (`loop.ts:1581`) and `nextElectionDay = currentDay` (snap).

### Konstruktives Misstrauensvotum

Action: `file_misstrauensvotum` (opposition only, max 1/turn, blocked during election). Tally: `tallyMisstrauensvotum()` — 85 % other-opposition joins the proposer.

- **`confidence_vote_filed`** + outcome (`loop.ts:1631`, `1638`).
- If passed: **`government_dissolved`** + **`government_formed`** + **`government_cabinet_formed`** (`loop.ts:1655-1715`). New coalition = proposer + all other former-opposition parties; old coalition → opposition.

### Presidential veto (Bundespräsident)

- **`presidential_veto`** (`veto.ts:34`) — 1–6 % chance based on impact magnitude. Bill flipped to `rejected` with `vetoedByPresident=true`. Proposer approval −`VETO_PROPOSER_APPROVAL_PENALTY`. `(⚠ invisible to users)` — not in `EVENT_CATEGORIES`.

### Bundesverfassungsgericht challenge

Action: `file_constitutional_challenge` (any Fraktion, target passed bill ≤14 days old, max 1/day globally). 30 % strike-down probability (`adjudicateChallenge()`).

- **`constitutional_challenge_filed`** (`loop.ts:1763`).
- **`constitutional_court_ruled`** (`loop.ts:1772`) — decision `struck_down` or `upheld`. Pre-canned German reasoning strings (no AI call).
- On `struck_down`: bill → `struck_down`, `reverseBillImpact()`, sentiment −0.5 − |impact|.
- Approval: struck_down → filer +0.8, proposer −0.5; upheld → filer −0.3.
- `(⚠ invisible to users)` — not in `EVENT_CATEGORIES`.

## 8. Media, polling, public opinion

### Media

- **`generateDailyMedia()` / `buildMediaBatchRequest()`** — 2–3 articles/day at end of `runDay()`. 3 outlets with fixed bias: Berliner Tagesspiegel (center), Volksstimme (left), Wirtschaftswoche (right). Only generates if newsworthy events exist. **Stored in `media_articles`, not emitted as a sim event.**
- `applyMediaSentimentFromArticles()` — moves `publicSentiment` ±0.5/day cap.
- UI label `media` in `EVENT_CATEGORIES.system` would match — but no event of that type is ever created. `(⚠ defined but not created)`.

### Polls

- **Party preference poll** (deterministic) — created every `POLL_INTERVAL` (15 d) (`loop.ts:1914`).
- **Context poll** (AI, single call) — created every `POLL_INTERVAL` (`loop.ts:1960`).
- **Poll resolution** (`resolveExpiredPolls()`) — winner boost +POLL_WINNER_APPROVAL_BOOST; no sim event.
- Polls type enum (`poll`) listed in `ROUTINE_EVENTS` but never emitted — `(⚠ defined but not created)`.

### Public opinion mechanics

- Sentiment range 5–75, baseline 45, mean-reversion 3 %/day, daily noise ±0.4.
- `applyDailyApprovalDrift(parties, actions)` — inactivity penalty, action rewards.
- Zero-sum normalization: 80 % of daily net approval change redistributed (`normalizeApprovalChanges()`).
- Membership bonus (logarithmic curve, `membershipBonus(activeMembers)`).

### Citizen questions (Bürgerfragen)

- Users submit via `POST /api/questions`; max 3/party/day, 14-day expiry, community upvote/downvote.
- `answerPendingQuestions()` — per-party batch AI answer (up to 50 per party). Top-voted first. No sim event; just updates `citizen_questions` row.
- Spam/duplicates auto-moderated (`question-moderation.ts`). `maybeGenerateBotQuestionPool()` pre-generates tagged questions for bot users.

### Referendums

- Generated by AI every `ECONOMY_INTERVAL` (30 d) if none active (`buildReferendumBatchRequest()` — `referendums.ts:214`).
- 14-day active window; 10-vote quorum.
- Resolution emits `day_start` (title "Referendum passed/rejected/expired"). `(⚠ type overloaded)` — `IMPORTANT_EVENTS` lists `"referendum"` but no code emits it.

## 9. MdB / participatory

All user interactions with Bundestag seats. Enabled/disabled per preset via `FEATURE_AVAILABILITY`.

### Applications + seats

- **Applications** stored in `mdb_applications` (USER DB). AI-reviewed daily (`reviewMdbApplications()`) via batch — up to 3/party/day, priority+lottery fair allocation, 14-day rejection cooldown. No sim events; just updates status.
- **Seats** in `bundestag_seats` (SIM DB). Allocated per-party after elections (`allocateSeats()`) — human / bot / ai split by preset (`HUMAN_SEAT_RATIO`, `BOT_SEAT_RATIO`). Seat reset on new election: all pending applications → `expired`.

### Voting

- `mdb_votes` (USER DB). `tallyVotes()` splits human-voted / proxy (default `party_line`) / AI seats. Discipline level 3 whips the vote.
- No sim event for individual MdB votes (aggregated into `bill_passed`/`bill_rejected`).

### Speeches

- Submitted on 2nd/3rd-reading bills; 1 per reading per user.
- Sim event `mdb_speech` emitted at end of `processDaySpeeches()` (`speeches.ts:155`). Sentiment ±0.1 or 0 based on batch-AI classification (short speeches auto-neutral).

### MdB-filed parliamentary actions

Queued as `pending_injections` with type prefix `mdb_`:

- `mdb_motion` → `motion_submitted` + outcome (`mdb-actions.ts:54`).
- `mdb_interpellation` → `interpellation_filed` (`mdb-actions.ts:112`).
- `mdb_amendment` → `amendment_proposed` (`mdb-actions.ts:155`).

### Internal proposals (caucus)

- Members + AI submit to `internal_proposals` (USER DB). 5-day review window; max 5 open/party; ≥3 votes required.
- Daily `reviewInternalProposals()` (batch AI per party) selects top 2:
  - `member_proposal_accepted` → creates bill with `memberInitiative=true` (`internal-proposals.ts:176`).
  - `member_proposal_declined` (`internal-proposals.ts:209`).
  - Expiry → no sim event, just `proposal_expired` notification.
- Note: `AI` also mirrors `propose_bill` actions into `internal_proposals` (`loop.ts:1174`) so the caucus list stays consistent.

### Member signals

- `member_signals` (USER DB). YES/NO bar on 2nd/3rd-reading bills. Counts injected into `AgentContext.memberSignals`. Triggers `bill_outcome` notification. No sim event.

### Discipline

- `reviewPartyDiscipline()` every 7 sim days (`loop.ts:1845`). 4 levels (Gut / Verwarnung / Eingeschränkt / Fraktionszwang / Ausschluss). Deterministic disloyalty score + batched AI reasoning. Expels at level 4 (seat → AI, `controller="ai"`, `userId=null`).
- No sim events; `mdb_discipline` and `mdb_expelled` user notifications.

### Sidejobs (scandals)

- Every 30 sim days, batch AI generates 3–5 fictional Nebentätigkeiten for random AI seats (`sidejobs.ts`).
- **`sidejob_scandal`** (`sidejobs.ts:111`) — emitted only for `isControversial: true` entries. Approval impact −0.2 to −0.5.

### Bot activity (`scripts/run-bot-activity.ts`)

Bot users perform user-equivalent actions on 4 h ticks with probability per engagement level (high 30 %, medium 15 %, low 5 %, lurker 2 %). Action types (by style weights): `vote_question`, `vote_proposal`, `signal_bill`, `ask_question`, `submit_proposal`, `submit_speech`, `vote_poll`, `apply_mdb`. Bots use the same endpoints as humans — no bot-specific events.

### Crisis templates (`config/crises.ts`)

Daily 8 % trigger + monthly extra 25 % roll. Max 2 concurrent. Severity: `low`/`medium`/`high`. Duration per template (`durationDays[min,max]`). On start: sentiment −1/−2/−3. Events:

- `crisis_start` (fresh + injected)
- `crisis_end` (auto-resolved when `currentDay >= endDay`)

### Calendar (`calendar.ts`)

Sim day ↔ real calendar date. 9 German national public holidays per year (`germanPublicHolidays()`). Helpers:

- `isWorkday()` — Mon–Fri, not a public holiday.
- `snapToNextWorkday()` — cycle hits snapped forward.
- `snapToNextSunday()` — election day snaps to Sunday.
- `isRealisticSessionDay()` — weekly Plenarsitzung alignment (used via `isSessionDay`).

No sim events from the calendar itself — holidays/weekends just move cycle days.

### Upcoming events API (`/api/calendar/upcoming`)

Projects future scheduled events (next election, budget cycle, referendum deadline, etc.) — read-only view, no events emitted.

## AI call map (batch vs sequential)

All sim AI calls run through `submitBatch()` (Anthropic Message Batches API — 50 % discount). Named batches:

- **Knowledge digest** — weekly, single-call batch. (`loop.ts:1024`)
- **Era summary** — every 60 d, single-call batch. (`loop.ts:1059`)
- **Briefing** — daily cross-party narrative, single call. (`loop.ts:1077`)
- **Party agents (group A)** — 6 simultaneous calls (one per party). (`loop.ts:1131`)
- **Interpellations (part of group B)** — up to 2/day. (`interpellations.ts` → `loop.ts:1855`)
- **Discipline (part of group B)** — every 7 d, per-party reasoning. (`discipline.ts:169`)
- **Speech flagging** — per bill, batched. (`speeches.ts:100`)
- **Citizen Q&A** — per party, batch of up to 50 questions. (`questions.ts:75`)
- **Internal proposals rank** — per party, rank-select top 2. (`internal-proposals.ts:115`)
- **MdB applications** — per party, batch ranking.
- **Bot question pool** — generates tagged questions for bots.
- **Mid-cycle (context poll + referendum)** — 1–2 calls per batch. (`loop.ts:1943`)
- **Sidejobs** — single call every 30 d. (`loop.ts:2187`)
- **Media + summary (end-of-day)** — 2 calls in one batch. (`loop.ts:2232`)
- **Negotiation synthesis** — single Sonnet call (non-batched fallback exists). (`negotiations.ts`)
