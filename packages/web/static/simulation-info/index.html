Technische Details zu KI-Modellen, Architektur, Kosten und API.

KI-Modelle

Jede Partei wird von einem eigenen KI-Modell gesteuert. Die Modellauswahl spiegelt die politischen Eigenschaften der Partei wider:

ParteiModell
SPDAnthropic Claude Haiku
CDU/CSUAnthropic Claude Haiku
GrüneAnthropic Claude Haiku
FDPAnthropic Claude Haiku
Die LinkeAnthropic Claude Haiku
AfDxAI Grok 3 Mini

Neben den Parteimodellen gibt es spezialisierte Rollenmodelle:

  • MODEL_DAILY — Tagesablauf, Gesetzentwürfe, Stellungnahmen (Claude Haiku)
  • MODEL_NEGOTIATION — Koalitionsverhandlungen (Claude Haiku)
  • MODEL_SYNTHESIS — Übergreifende Zusammenfassungen, Ära-Berichte (Claude Sonnet)

Alle Modelle sind über Umgebungsvariablen überschreibbar (MODEL_PARTY_<ID>, MODEL_DAILY, MODEL_NEGOTIATION, MODEL_SYNTHESIS).

Kontext-Tiefe

Die Kontext-Tiefe bestimmt, wie viele historische Informationen die KI bei jeder Entscheidung berücksichtigt — und beeinflusst direkt die Kosten:

TiefeKosten / TagBeschreibung
Lowca. $0,03Minimaler Kontext, schnelle und günstige Simulation
Normal (Standard)ca. $0,055Ausgewogener Kontext für realistische Abläufe
Highca. $0,09Umfangreicher Kontext, detailliertere KI-Entscheidungen

Alle 60 Simulationstage (bei Normal/High) erstellt die KI komprimierte Ära-Zusammenfassungen mit strukturierten Fakten zu Wirtschaft, Koalitionen, Gesetzen und Wahlen.

Architektur

KAI Bundestag ist als Monorepo mit vier npm-Paketen aufgebaut:

  • types — Reine TypeScript-Typdefinitionen (emitDeclarationOnly), kein Runtime-Code.
  • engine — Simulationskern: KI-Agenten (Vercel AI SDK), Datenbankzugriff (Drizzle ORM + better-sqlite3), Tagesablauf (runDay()).
  • api — Express REST-Server mit 11 Domain-Routern, importiert aus engine und types.
  • web — React 19 Single-Page-App (Vite + React Router v7 + Tailwind CSS v4 + shadcn/ui).

Abhängigkeitskette: types ← engine ← api. Das Web-Paket ist eigenständig ohne Workspace-Abhängigkeiten.

Alle Pakete nutzen ESM ("type": "module"). Die Datenbank liegt in data/simulation.db (SQLite), der Pfad wird über import.meta.url aufgelöst.

Simulationsaktionen

An jedem Simulationstag führt die Engine folgende Aktionen aus:

  • Jede Partei schlägt optional einen Gesetzentwurf vor
  • Parteien kommentieren und debattieren bestehende Entwürfe
  • Abstimmungen über reife Gesetzentwürfe werden durchgeführt
  • Parteien veröffentlichen Pressemitteilungen und Stellungnahmen
  • Drei Nachrichtenredaktionen erstellen Artikel zum Tagesgeschehen
  • Wirtschaftsindikatoren werden aktualisiert (alle 30 Tage)
  • Umfragewerte werden neu berechnet (alle 15 Tage)
  • Zufällige Krisen können auftreten und die Parteien zur Reaktion zwingen
  • Haushaltsdebatte und -abstimmung (jährlich)
  • Wahlzyklus und Koalitionsverhandlungen (alle 4 Jahre)

Batch-Verarbeitung

KAI Bundestag nutzt die Anthropic Message Batches API, um KI-Anfragen zu bündeln. Statt jede Anfrage einzeln zu senden, werden mehrere Anfragen in einem Batch zusammengefasst.

Dies bringt zwei wesentliche Vorteile:

  • Kostenersparnis: Bis zu 50 % geringere API-Kosten gegenüber Einzelanfragen.
  • Effizienz: Parallele Verarbeitung mehrerer Parteiaktionen in einem Durchlauf.

Batch-Verarbeitungsparameter sind über die Umgebungsvariablen BATCH_POLL_INTERVAL und BATCH_TIMEOUT konfigurierbar.
